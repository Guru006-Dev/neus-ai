# ADIP — Autonomous Product Intelligence Platform

ADIP turns one written goal (for example *"Analyze the onboarding flows of three note-taking apps"*)
into a run of six cooperating agents: **Explorer → Knowledge Graph → Documentation → QA → Demo →
Release**. Its web frontend is **NEXUS**: a scroll-driven 3D landing page that tells the story of one
run, and a dashboard for starting runs and following them live.

## Repository layout

| Path | What it is |
|---|---|
| `backend/` | FastAPI server (`main.py`) and the orchestrator engine (`agents/orchestrator/`): planner, router, priority queues, per-agent concurrency limits, scheduler, worker pool, SQLite persistence and the six built-in agents. Also serves the built frontend (`frontend_serving.py`). |
| `frontend/` | NEXUS web app: React 19, TypeScript, Vite. `src/landing/` is the 3D landing page (three.js via react-three-fiber, GSAP ScrollTrigger); `src/dashboard/` is the run dashboard. |
| `agents/` | Six standalone MCP servers (`explorer`, `knowledge`, `documentation`, `qa`, `demo`, `release`) plus `shared/mcp_agent_server.py`. Each runs over stdio with the FastMCP server bundled in the `mcp` package. |
| `start.js`, `build.js`, `package.json` | Linux deployment wrappers (`npm run build` / `npm start`): they prepare a Python virtual environment and launch `backend/main.py`. |

## How a run works

1. `POST /workflows` with a goal. The router picks a plan: a goal mentioning *qa*/*test*, *doc* or
   *demo* gets a three-step plan (Explorer, Knowledge Graph, then that agent); any other goal gets
   all six agents.
2. The scheduler runs the plan one step at a time on the worker pool, within each agent's
   concurrency limit (Explorer 5, Knowledge Graph 10, Documentation 10, QA 4, Demo 2, Release 5).
   Each agent's output is merged into the workflow context for the next one.
3. Workflow and task state is stored in SQLite, so finished runs can still be read after a restart.
4. If an agent raises an error, its task and the workflow are marked `FAILED`; later steps are not run.

The built-in agents call Gemini when `GEMINI_API_KEY` is set. Without a key they return
deterministic offline results, which is enough to run the whole pipeline and all tests locally.

## Prerequisites

- Python 3 with `pip` (developed and tested with Python 3.14)
- Node.js and npm (developed and tested with Node 24)

## Install

```bash
pip install -r backend/requirements.txt
cd frontend && npm ci && cd ..
```

Optional: `psutil` (CPU/memory readings used for load shedding) and `google-genai` (only for
`GET /check-veo`). The `agents/` MCP servers need `mcp`; Explorer and Release also use the packages
in their `agent/requirements.txt` (Playwright, pydantic-settings, loguru, networkx, tenacity) and a
Playwright browser (`playwright install chromium`).

## Run locally

```bash
cd frontend && npm run build && cd ..   # produces frontend/dist
python backend/main.py                  # http://localhost:3000
```

`/` serves the landing page and `/dashboard` the dashboard. Without `frontend/dist` the API still
runs, but `/` shows a "Dashboard Not Found" page, so build the frontend first.

**Frontend development:** run the backend as above, then `cd frontend && npm run dev`. Vite proxies
`/workflows`, `/system` and `/api-key` to port 3000 (`NEXUS_API_PORT` overrides the port).

**An agent MCP server on its own:** `cd agents/<name> && python server.py` (stdio transport).

### Configuration

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `3000` | Backend HTTP port |
| `DB_PATH` | `orchestrator_jobs.db` in the working directory | SQLite database (`*.db` is gitignored) |
| `GEMINI_API_KEY` | unset | Optional. Enables Gemini for the built-in agents. The dashboard's Settings page can also set it at runtime (`POST /api-key`); it is kept in process memory only. |
| `NEXUS_API_PORT` | `3000` | Backend port used by the Vite dev/preview proxy |

## API

| Method and path | Purpose |
|---|---|
| `POST /workflows` | Start a run. Body: `{"goal": "...", "user_id": "...", "priority": 1}`; returns `{"workflow_id", "status": "SUBMITTED"}` |
| `GET /workflows/{id}` | Run status, plan context and per-task results; `404` for an unknown id |
| `GET /workflows/{id}/demo_html`, `/explorer_html` | HTML generated by the Demo and Explorer agents |
| `GET /system/status` | Job summary, per-agent concurrency, queue lengths and resource readings |
| `POST /api-key` | Set the Gemini key for this process |
| `GET /check-veo` | Whether the configured key can see Veo video models |

`POST /analyze` and `GET /status/{id}` are older compatibility endpoints; the NEXUS dashboard uses
`/workflows` instead.

## Tests

```bash
cd backend && python -m pytest tests -q   # orchestrator, endpoint and frontend-serving tests (no server needed)
cd frontend && npm test                   # unit tests (Vitest)
cd frontend && npm run test:e2e           # browser tests (Playwright): landing page and dashboard
cd frontend && npm run lint               # oxlint
```

The backend tests run the real orchestrator in-process against temporary databases, with no network
access. The dashboard browser tests use recorded backend responses (`frontend/e2e/fixtures`). The
Explorer and Release MCP packages have their own suites (`cd agents/explorer/agent && python -m pytest`).

## Current limitations

- **Local only.** There is no verified production or cloud deployment. `npm run build` / `npm start`
  target a Linux host with an `/app` directory and do not build the frontend; run
  `cd frontend && npm run build` separately.
- **Two separate agent implementations.** The backend runs its own six built-in agents
  (`backend/agents/orchestrator/registry.py`); it does not call the MCP servers in `agents/`.
- **Offline results are placeholders.** Without `GEMINI_API_KEY` the agents return deterministic,
  template-based output rather than real research, and agent-reported metrics are illustrative.
- **No automatic retries.** A failed agent fails the whole run.
- **The 3D landing page** needs a landscape viewport at least 1024 px wide, WebGL, and no
  reduced-motion preference; otherwise it shows a 2D version of the same story.
